## 是什么

一个面向"人与智能体对话"这一场景的组件集，共二十一组：加载态、思考轨迹、流式文本、审批卡片、工具调用标签、任务行、聊天面板、输入条、推荐卡、上下文卡、差异表、记录表、筛选表、侧边导航、搜索、流程图、洞察卡、代码块、微调卡、划选操作、智能体屏幕。

每一组都是可直接复制粘贴的成品，带真实动效与交互，不是静态效果图。加载态给了五种形态并显示已用时间；思考轨迹可以展开成步骤、推理、检索、编码四类；审批卡片就是智能体动手之前回头问人一句的那种组件，带选项与进度。

站点的演示统一用一个虚构的冰淇淋品牌做场景，数据前后连贯，因此能看到同一份数据在不同组件里的呈现方式。

## 解决的问题

智能体类产品的界面元素，通用的组件库基本没有覆盖：思考过程怎么展示、工具调用怎么折叠、需要人确认时怎么问、长任务的状态怎么标、流式输出怎么接来源引用。这些要么自己从零设计，要么照抄某个产品的实现，而多数产品的实现并未开源。

这二十一组填的正是这段空白。它们是成品级的设计，配色、间距、圆角、动效都调过，粘进项目里就能用，也可以作为设计的起点改。作者是产品设计工作室，这套东西本身也是他们的作品展示。

## 注意事项

只提供页面上的代码，没有 npm 包，也没有组件文档站。升级要自己去网站上重新复制，版本差异无从追踪；组件之间的依赖关系（例如某个卡片用到的内部基元）需要读代码确认。

代码是 React 与 TypeScript，动效依赖 Motion。换到 Vue、Svelte 或原生环境，结构与动画都得自己重写。

MIT 许可要求保留版权声明。商用、修改、再分发都可以，但版权与许可文本不能删。

组件面向的是聊天与智能体场景。做通用后台、表单密集型系统，这套的覆盖面不够，仍需搭配常规组件库。

站点由个人工作室维护，没有服务承诺。组件数量不多、更新节奏取决于作者，作为参考与起点合适，作为长期依赖的组件基础需要自行接管维护。

## 不适用场景

- 需要按版本锁定、可追溯变更的团队依赖。
- 非 React 技术栈、无法直接使用其组件代码的项目。
