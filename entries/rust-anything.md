## 解决的问题

把一个现成的项目用 Rust 重写，难点不在写，而在证明重写之后行为没变。人肉对拍要跑两遍测试、比两遍输出，改到第三轮就没人愿意再比了。

rust-anything 把这个过程固定成三步：先对着原程序录一遍行为——命令行输出、HTTP 响应、测试结果都可以；再由编码智能体一段一段写成 Rust；每写完一段就与录下的行为比对，对不上就退回重写，对上了才继续下一段。它不翻译代码，只负责证明改写后行为相同。

这套流程已经沉淀出可以直接用的成品：eslint-rs 用 npm 装上就是一个跑 Rust 实现的 ESLint，覆盖 90 条规则，剩下的交给同版本的 ESLint 10.15.0 兜底，输出完全一致；prettier-rs 回放了 17,224 次录制的运行结果。也就是说，即使不自己改写，也能直接把这两个替换品装进项目里用。

## 评分依据

- **开箱即用**：通过。预编译二进制、npm 与 cargo 三条安装路径，产出的 eslint-rs 可独立运行。
- **维护活跃**：最近一次提交于 2026-11-23。
- **文档充分**：README 给出记录、改写、校验的完整命令，并说明各语言的边界。
- **版本规范**：当前版本 v3.4.0，遵循语义化版本并附发布说明。
- **有示例**：通过。demo 目录内含多组可运行的示例工程与对照实现。

## 注意事项

保证的强度取决于录到的行为。没录到的路径、没覆盖的分支，改写后是否一致无从判断，测试用例的质量直接决定结论的可信度。

跨语言边界的部分仍要人工处理。TypeScript、Python、C、Go、Ruby、Java 各自有对应的 FFI 方案（NAPI、PyO3 等），类型映射与内存归属出错时，行为比对能报出差异，但改法还得自己想。

预编译的端口程序覆盖 macOS 与 Linux 的 x64、arm64；在 Windows 上运行时，eslint-rs 会退回到调用 ESLint 本体，输出一致但没有加速。

## 不适用场景

- 行为本身没有稳定预期、每次运行都不同的程序。
- 只想要一次性的性能修补，而不打算改动代码结构。
