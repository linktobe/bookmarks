## 解决的问题

一份技能文档通常有三种来路：手写、让强模型一次生成、或者靠松散的自我修订。三种都不像优化器——起点多高往往就是终点多高，反馈进来也不保证能更好。

SkillOpt 把技能文档视作冻结智能体的可训练状态，用训练神经网络的纪律去训练它。一轮循环是：目标模型在任务上跑出带分数的轨迹，另一个优化器模型把轨迹读成对同一份文档的有界增删改，候选编辑只有严格提升留出验证分才被接受。配套的有文本学习率（每步允许的最大编辑数）、余弦学习率调度、被拒编辑缓冲，以及按轮次做一次慢更新与元技能记忆。

部署产物是一份 best_skill.md，通常三五百到两千 token，对着未改动的目标模型运行，推理时零额外调用。

论文给出的结果覆盖六个基准、七个目标模型与三种执行壳（直接对话、Codex CLI、Claude Code CLI），五十二个格子里全部最优或并列最优；在 GPT-5.5 上，无技能基线平均被抬高 23.5 分（直接对话）、24.8 分（Codex 循环内）、19.1 分（Claude Code 内）。技能产物还能跨模型规模、跨两种执行壳、跨邻近基准迁移。

另有一条离线支线 SkillOpt-Sleep：夜里读本地会话记录，收获反复出现的任务，重放一遍，再在留出门禁之后把验证过的技能固化下来。

仓库里还附了论文表一的六份成品技能，每个基准一份，两三千到一万三千字符，末尾带一段受保护的慢更新段落，用来承载跨轮次的长程指引。不跑训练也能把这些技能挂进评估脚本复现分数。

## 注意事项

装完只是拿到框架。要跑通第一个实验，需要至少一个配置好的模型后端（Azure OpenAI、OpenAI 兼容端点、Claude CLI、本地 Qwen 等选一），把 .env 里的凭据手动 export 进当前 shell——程序不会自动读它；SearchQA 还要先运行物化脚本，把发布出来的 ID 清单还原成可运行的训练与测试集。

训练本身是两次调用：优化器读轨迹、目标模型跑任务，账单按两倍算；耗时取决于基准规模、模型延迟与并发数，官方明确不给固定时长承诺。

PyPI 上的 0.2.0 落后于 main。通用 openai_compatible 后端、Sleep 对非 Azure 兼容端点的支持、Cursor 与 Pi 相关支持都在 0.2.0 之后才落地，要用这些得从源码安装。

WebUI 默认只监听回环地址，暴露到 0.0.0.0 或开公开分享链接之前必须设置账号密码，否则会直接拒绝启动。

论文的数字建立在特定基准与模型上。搬到自有任务时，门禁的留出集要自己划；留出集与真实分布错位，这套循环就退化为没有保证的自动改写。

## 不适用场景

- 手边没有可用模型后端，或不愿为训练付账。
- 一件事写一段提示词就能解决，不需要迭代优化。
- 需要确定的完成时间与成本上限。
