## 解决的问题

编码智能体在缺乏约束时会跳过步骤：没写规格就直接动手，没跑测试就宣布完成，评审只看风格不看风险。问题不在模型能力，而在流程没有落成可执行的规则。

这套技能把开发过程切成六段——定规格、做计划、实现、验证、评审、发布，每段对应固定的检查项与产出物。十条命令分别挂到对应阶段，智能体在执行时按技能里写明的顺序推进，而不是凭上下文自由发挥。

技能内容以 Markdown 写成，包含质量门槛与常见反例，可直接阅读、修改或按团队习惯覆盖。

## 注意事项

安装有两条路径：一条命令 `npx skills add` 可装入七十余种智能体，或在 Claude Code 里通过插件市场安装。命令与内置命令重名时需用带命名空间的写法。

技能是通用流程，不含具体技术栈的判断。团队若已有自己的规范，建议在装载后逐条改写，而不是直接沿用。

## 不适用场景

- 需要智能体自主探索、不预设流程的场景，强流程反而拖慢节奏。
- 一次性脚本或实验代码，跑完整套流程的成本高于收益。
