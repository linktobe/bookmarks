## 解决的问题

笔记类工具的两难很具体：托管在别人的服务上，等于把内容交出去；自己架一台服务器，则要养机器、做备份、盯证书，成本远高于记笔记这件事本身。

NoteFlare 把加密放在浏览器里：口令经 Argon2id 派生，内容用 AES-256-GCM 加密后才上传，服务端拿到的只有密文。运行环境只需要一个 Cloudflare Worker 与一个 D1 数据库，都落在免费额度内，访问入口再套一层 Cloudflare Access，限定只有自己的邮箱能打开。

部署被拆成了三次点击：一键部署按钮建起 Worker 与数据库，粘贴一枚临时 API 令牌配好登录，再设置口令并记下恢复码。作者给的估算是全程约 10 分钟、不需要写代码，不想点网页也有命令行路径。

功能上没有因为"轻"而缩水：Markdown 笔记支持表格、引用、代码高亮与可勾选清单，笔记能置顶、拖动排序、贴八种纸质颜色、打标签、设提醒，回收站 30 天后自清。导入支持整目录 Markdown（Obsidian 库可以直接拖进去）、Google Keep、Evernote、Simplenote 与 Standard Notes 的导出包。

## 注意事项

口令与恢复码同时丢失，笔记就无法恢复。这不是设计缺陷，而是端到端加密的必然结果——服务端没有可以帮忙解开的东西。README 把这一点放在最上方提醒。

依赖 Cloudflare 的免费额度：Worker 与 D1 的读写次数有上限，个人使用远够，多人共用或大量附件需要看配额。

自动部署与后续升级走 Workflows 与 wrangler，Cloudflare 侧接口或价格政策变化时会受影响；数据虽然加密，但仍托管在 Cloudflare 上，账密体系也由它承担。

## 不适用场景

- 需要多人协同编辑同一份笔记。
- 无法接受"口令丢失即数据丢失"的团队。
