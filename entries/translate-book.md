## 解决的问题

整本书翻译卡在上下文上。整本塞进一次会话，超出窗口就开始截断；逐段翻，人称、术语与语气前后接不上，读起来像几个人各翻了一部分。

这个技能换了做法：先用 Calibre 的 ebook-convert 把 PDF、DOCX 或 EPUB 转成 HTMLZ，再转 HTML 与 Markdown；版面复杂的 PDF 可以先用版面感知的解析器出 Markdown，跳过 Calibre。然后切块，用 manifest.json 记录每块的 SHA-256。

关键一步是分块翻译：每块交给一个独立的子智能体，默认八路并发，各自带全新上下文。这既避免了上下文累积导致的输出截断，也让每块都能稳定用完自己的额度。相邻块之间可以读一小段只读的前后文，用来解决代词指代与实体译名。翻完校验 manifest 哈希与源文、译文的 1:1 对应，合并后经 Pandoc 出 HTML（带浮动目录）、DOCX、EPUB 或 PDF。

断点续跑按块记录，术语敏感的重译写在 run_state.json 里。

## 注意事项

依赖链偏长：一个支持子智能体的 Agent 宿主，加上 Calibre 的 ebook-convert 与 Pandoc。缺任何一环都会停在第一步；公式与表格密集的 PDF 还要另接版面感知的解析器。

它自己不调用任何模型接口。翻译跑在你的 Agent 里，费用、限速与可用模型都由宿主决定；八路并发容易撞到速率限制，书越长越明显。

哈希校验保证的是「没有旧块混进来」与「源译一一对应」，不保证译文质量。术语一致性主要靠 glossary 与相邻块上下文，专业书仍建议人工通读。

长书的耗时以小时计，中途断电或退出可以续跑，但已付的调用不会退。

仓库无版本标签，也没有可直接查看的成品样例。

## 不适用场景

- 只有几页文档要翻，直接贴进对话框更快。
- 书有 DRM，或不能合法转换。
