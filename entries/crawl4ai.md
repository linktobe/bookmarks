## 解决的问题

模型的输入需要干净文本，网页却是给人看的：导航栏、页脚、推荐位、广告、JavaScript 渲染出来的正文，混在一起。抓下来容易，洗干净难；要结构化的字段，还得再写一遍选择器。

Crawl4AI 把这一段做成一条流水线。默认输出是保留标题层级、表格与代码块的 Markdown，页面链接变成编号引用；三种内容过滤（剪枝、BM25、按查询的 LLM 过滤）可以把菜单与页脚剔掉，只留下正文。

要字段就走结构化提取：CSS、XPath 与正则三种 schema 不需要模型，快且稳；说不清结构时用 schema 生成器描述一次，让它写出可复用的 schema；需要语义判断时改用 LLM 提取，输出到指定 JSON 结构。长页面可按主题、正则或句子切块，再用余弦相似度挑出与查询相关的块，正好接 RAG。

工程侧有异步浏览器池与缓存，会话、代理、Cookie、用户脚本与钩子都可接管，另有一套自适应爬取，会从站点结构里学路径。

## 注意事项

安装分两步：pip 装库，crawl4ai-setup 再装浏览器，后者要下载几百 MB，第一次慢。

三种落地形态的代价不同。库模式把浏览器跑在自己的进程里，代理、反爬、并发都得自己配；Docker 服务模式多一层网络与鉴权，记得自己设访问 token，别裸奔在公网；托管接口替你跑浏览器，每月一千免费额度，套餐从十美元起，但抓取行为出了你的机器。

抓取要守规矩：目标站的 robots 与服务条款仍然适用，高频请求会被封 IP，生产环境通常需要限速与代理池。

免费额度按 credits 计，不是按页计，具体换算看官方文档。

## 不适用场景

- 只需要抓一两个静态页面，写个 requests 更快。
- 需要登录态深抓、且不接受自己维护浏览器指纹与代理。
