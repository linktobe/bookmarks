## 解决的问题

让编码智能体修一个缺陷，结果往往取决于这一次运行：可能跳过方案、忘了跑测试、自己评审自己，也可能做到一半停下而没人发现。做演示可以，团队交付不行。

LoopForge 给这类工具加上外面一层。两种用法：一是与 Main Bot 对话，它按需开一个带项目仓库的 Docker 沙箱，把任务拆给项目角色这些子智能体；二是跑 SOP——由智能体节点、脚本节点与人工关口串成的固定流程，每次运行有独立沙箱，可审批、可打回指定环节返工、可从任意节点重跑。

干活的是各家命令行工具，README 列了十种：CodeBuddy、Codex、Claude Code、OpenCode、Cursor CLI、Antigravity、Kimi Code、Pi、DeepSeek Harness 与 ZCode。LoopForge 负责角色提示词、沙箱、检查点与留痕；方案、实现、评审、测试各有独立的执行器、模型与工具配置。

两种方式挂在同一套需求上，无论改动来自对话还是流程，都能追到原始需求，并计入交付与成本统计。内置后端、前端、缺陷修复、产品方案四类 SOP 可直接起步。

部署走 Docker：start.sh 拉取固定版本的镜像，建 MySQL，生成配置与会话密钥，导入内置沙箱与体验项目，不需要在宿主机装 Go 或 Node。

## 注意事项

需要 Docker、Compose、Python 3 与 curl，安装脚本会先检查，缺什么在确认后补装；镜像拉取需要可用的外网连接。

国内拉 ghcr.io 容易中断。脚本会并行探测南京大学镜像，但只在两边 manifest 摘要一致时才采用；拿不到官方摘要就仍走官方源。

服务默认监听 0.0.0.0:8090，第一个注册的账号自动成为管理员。建号之前应限制来源 IP，或先配好 HTTPS 反向代理。

真正跑任务要配模型凭据；改已有仓库并提交 PR 还要接通 GitHub。只有内置的体验流程——脚本加人工审批——不需要任何 Key。

许可为 MIT，但第三方组件另有许可，见 THIRD_PARTY_NOTICES。仓库里的 local/ 是旧的本地版，与平台版不是一回事。

## 不适用场景

- 单人做小改动，直接开一个智能体会话更快。
- 不提供 Docker 环境，或需要完全离线运行。
