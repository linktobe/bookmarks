## 解决的问题

改 Windows 的体验通常只有两条路：装一套美化软件，或者自己写 hook。前者往往要替换系统文件、全家桶式安装；后者要懂逆向，还得处理全局注入的坑。Windhawk 走中间那条：装一个引擎常驻，模组以源码形式从市场取，注入到指定进程里生效。装模组是点两下的事，模组本身是可读的源码，不是黑盒。

现有的模组覆盖的都是具体的小痛点：任务栏放到顶部、任务栏显示标签、资源管理器显示更精确的文件大小、开始菜单改样式。模组页面标着使用人数，任务栏标签那个有三万八千多人在用。

## 注意事项

全局注入与 hook 的本质是把第三方代码塞进别人的进程，模组虽然以明文源码分发，稳定性和安全风险仍然存在：注入 explorer.exe 的模组写错，任务栏就没了。作者把稳定性列为最高优先级，但这件事没有绝对保险。

README 明确说这个仓库是用来报 issue 和讨论的，源码在 `src/`；自行编译的路径是解出便携版、构建要改的部分、替换对应文件。要写模组，得去 windhawk-mods 仓库看例子，再对照作者的博客《Implementing Global Injection and Hooking in Windows》。

发布编号不统一（v1.7 与 v1.7.3 交替出现），按评分表的版本规范一项不通过。Windows 11 的部分模组与系统版本强相关，系统大版本升级后要等模组跟进。

## 不适用场景

- 需要签名、可审计、能进企业白名单的定制方案。
- 不允许向系统进程注入代码的合规环境。
- macOS 与 Linux。
