## 解决的问题

自建一个状态页，通常要一台服务器、一个监控服务和一个前端。Upptime 把三样都省掉：用模板建一个公开仓库，写一份 `upptimerc.yml` 列出要监控的地址，剩下的由 GitHub Actions 按分钟级节奏跑检查，结果提交回仓库，再生成状态页、事件历史与响应时间曲线。

数据以 git 提交的形式存在，天然有历史、可回溯、不需要数据库。要自定义域名，挂 GitHub Pages 即可。

## 注意事项

依赖 GitHub 的免费额度与调度精度：检查频率按 cron 走，实际触发会被推迟，五分钟的间隔常常变成十几分钟，不能当严格 SLA 监控。

仓库必须是公开的，否则 Actions 与 Pages 的组合不成立；这也意味着监控目标与响应数据对外可见。

GitHub 自己挂掉时，监控与被监控对象一起失联——这类工具的共同短板。通知支持邮件、Issue、Telegram 等，需要在仓库里配凭据。

## 不适用场景

- 需要秒级探测与告警的商业 SLA。
- 必须保密的内部服务监控。
- 需要多地域探测点的场景。
