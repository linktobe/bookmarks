## 解决的问题

同时用几个编码工具的人都会遇到同一件事：在 Claude Code 里讲过的项目背景，换到 Codex 要重讲一遍；昨天在 Cursor 里定下的约定，今天在 DeepSeek Harness 里没人记得。每个工具有自己的会话历史，互不相通。

Memmy 的做法是在本机起一个记忆服务，所有接入的工具共用同一份。它把三件事放在一起：记得（把协作历史整理成结构化记忆）、接力（换工具时把项目背景、偏好与进度带过去）、自己动手（它同时也是一个 Agent，能整理信息、续上未完成的任务）。

接入面铺得很宽：DeepSeek Harness、Claude Code、Codex、Cursor、OpenCode、Pi、WorkBuddy、OpenClaw、Hermes 都有对应插件或钩子。桌面端是主入口，另有命令行与 TUI 版；Linux 上会装成两个 systemd 用户服务，记忆服务在 18960，网关在 18990，网关对外是一个 OpenAI 兼容接口，别的工具填地址就能用。

数据留在本机：两个服务只监听回环地址，凭据写在 0600 的文件里。

## 评分依据

- **开箱即用**：官网或 Releases 下载桌面端，注册即得试用额度，装完就能跑。
- **维护活跃**：最近一次提交于 2026-11-24。
- **文档充分**：独立文档站之外，仓库内四条安装路径各自写全，含配置样例。
- **版本规范**：当前版本 v1.2.7，遵循语义化版本并附变更记录。
- **有示例**：未通过。Knowledge 与 plugins 为服务模块，仓库不含示例。

## 注意事项

桌面端注册会送试用额度，用完要切到自带 Key 的模式，在 ~/.memmy/config.yaml 里填提供商与模型。

Linux 的安装脚本对 Node 版本卡得很死：22.x 需 22.23.4 以上、24.x 需 24.22.1 以上、26.x 需 26.12.1 以上，其他大版本会被安装器直接拒绝。

安装器只装记忆服务，不会自动往 Codex、Claude Code、Cursor 里塞技能。要接入得自己跑 `memmy-memory init`，或指定单个 `--agent`。

记忆是共享的，接入的工具越多，越需要定期清理不该留下的内容；本地记忆一旦被读进上下文，等于所有接入的工具都能看到。

## 不适用场景

- 只用单一编码工具、也不跨设备。
- 需要团队多人共享同一份记忆——路线图上，尚未提供。
