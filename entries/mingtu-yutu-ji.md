## 解决的问题

读明史时，地名与战线散在正文里：土木堡在哪、萨尔浒三路怎么走、辽东是什么时候丢的。文字讲得清因果，讲不清空间；平面地图又装不下时间。

这个项目把 1344 到 1662 年的疆域变化、十二场多幕战役（共五十三幕、一百一十一条行军与海航箭矢）、古今地名对照放进一个三维 WebGL 场景，按年份推进，箭矢按战术先后分步出现，附自动运镜与「为啥会这样」的因果说明。

## 评分依据

- **开箱即用**：`npm install` 之后 `npm run dev`，打开 3000 端口即是完整场景，不需要任何 API key。
- **维护活跃**：最近一次提交于 2026-11-25。

## 注意事项

规模小：2026-11-14 建库，单人项目，几十颗星；功能表很全，但缺少多人长期使用后的磨损。

历史事件与数据的取舍由项目自行整理，当史料引用之前需要核对原始出处。

三维渲染吃显卡，README 给了省电、均衡、极致三档，集显轻薄本可用，复杂场景仍会掉帧，移动端体验有限。

没有发行版本，取的是主分支构建，数据与代码都在动。

需要 Node 20 以上；部署另有 Docker 方案，但涉及域名与证书配置。

## 不适用场景

- 需要严谨史学引用与原始文献链接的场合。
- 需要纯二维、轻量加载的页面。
- 低配设备或长时间的移动端浏览。
