## 解决的问题

在编码智能体里接模型，通常要注册账号、申请 Key、盯着配额。DeepSeek Harness 的这个插件绕开这几步：装上即有一条免费车道，不登录、不填 Key。

免费车道的上游是 OpenCode 的 Zen 网关与 Kilo AI 的公共网关，直连，不经第三方中转。模型清单每次刷新都向上游重新拉取，插件内不存静态快照；选择器只列出本机网络出口实测可路由的模型，被上游明确拒绝的移出下拉框并注明原因。

它还补了几件插件少做的事。思考强度不是塞进提示词，而是按上游声明的档位下发，没有档位菜单的模型改走输出 token 预算阶梯。另开一个本地 OpenAI 兼容端口，别的工具填 base URL 与 Key 就能用同一批模型，并且原生实现了 Anthropic 的 /v1/messages。请求前就地压缩工具输出，四十 KB 的 git diff 可去掉九成字节而模型仍能作答。

扩展面很宽：十个账号渠道、七十七家自带 Key 的聚合渠道、把多个模型串成降级链的 combo、本机用量看板，以及一套带签名校验与沙箱的插件市场。

## 注意事项

免费车道的可用性取决于上游公共网关的开放程度，规则与配额随时会变。上游按出口 IP 计配额，一次 429 会开一个默认六小时的窗口，窗口内插件本地拒绝新回合；车道可配独立出口代理。

Kilo 免费池的上游声明 prompt 可能被记录用于改进服务，敏感内容不要走这条车道。

十个账号渠道是用自己的账号登录第三方产品，这类用法可能与各家服务条款相冲突，风险由使用者承担。EAC 渠道需登录 GitHub 给仓库点 Star 解锁。

插件适配内核 0.1.5 至 0.1.7-rc.2，内核升级后需跟进。许可为 MIT，但免费模型本身不附带任何可用性承诺。

## 不适用场景

- 生产环境需要稳定 SLA 与可审计调用链。
- 完全不能接受请求经过第三方公共网关的场景。
