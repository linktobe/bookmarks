## 解决的问题

做短信通知或验证码，绕不开买通道：云通信平台按条计费，很多国家又根本买不到虚拟号码。而手边那台常年插着卡的安卓手机，本来就能收能发。

httpSMS 把这台手机变成网关。服务端提供一条 HTTP API，调用时经推送通道唤醒手机，由手机上的 App 发出短信；手机上收到的短信，也能转发到你指定的 webhook。号码还是原来那个号码，资费还是运营商的资费。作者给出的由来很直接：他来自喀麦隆，想在那些买不到虚拟号码的国家用 API 收发短信，找不到现成方案，于是自己写了一个。

几项设计值得记下来。端到端加密走 AES-256，密钥只存在手机上，服务端即使被完整看到也读不出短信内容。背压可以设成每分钟三条——即使一次调用发给一百个人，也会按这个速率排队发出。消息有效期解决的是手机长时间离线、推送没送达的情形：超过设定时长仍未发出的消息作废并通知你，而不是无限期挂在队列里。

官方另配了 Go 与 JavaScript/TypeScript 两个客户端库，接口风格一致。

## 注意事项

自托管的门槛不低。要建一个 Firebase 项目（用到云消息推送、邮箱密码登录、服务账号凭据，以及安卓侧的 google-services.json），配一个 SMTP 服务用于发送邮件，再申请 Cloudflare Turnstile 的站点密钥来保护消息搜索接口，最后才能在仓库里起 compose。README 把这五步写全了，但照做下来是一两个小时的事。

Firebase 的邮箱密码登录有个已知问题，会卡在登录环节，需要顺手关掉邮箱枚举保护；README 里给了绕法与上游 issue 链接。

服务端与手机端是两套配置，安卓的 google-services.json 必须与你自己的 Firebase 项目对上。任一处对不上，表现都是「手机收不到推送」，排查起来需要两边对照日志。

许可为 AGPL-3.0。自己用、内部用都不受影响；改完之后对外提供服务，修改的部分要一并开源。

短信资费由运营商按条计，网关省不掉这笔钱。群发之前先看清套餐与单条价格。

## 不适用场景

- 手边没有一张能长期插在机器里的 SIM 卡。
- 需要同时处理数千条、对吞吐有硬性要求的场景。
