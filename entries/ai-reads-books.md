## 解决的问题

把一本书丢给模型让它总结，得到的是浮在表面的概括：它没有真的读过，只是扫了一遍开头与结尾，中间靠猜。

这个脚本换成另一条路——一页一页读。每页记下学到的东西并标注页码，每二十页停下来写一次「到目前为止的理解」，读到最后一页再把全书拢成一份摘要。整个过程在终端里实时可见，能看到它翻到第几页、这一页记了什么。

输入支持 PDF、EPUB、Word、Markdown 与纯文本。PDF 用 PyMuPDF 按原页读，扫描件可开 OCR；其余三种用标准库直读，按约两千四百字符切页，总在段落边界断开，因此同一个文件每次切出的页一致，中断后能接着跑。

后端给了八个：Codex、Claude Code、Grok Build 三种按订阅账号走，不填 API Key；OpenAI、Anthropic、Gemini、xAI、OpenRouter 五种按 Key 走。

## 注意事项

每页一次调用，一本三百页的书就是三百多次；用 API Key 时要先算账，用订阅账号则受宿主额度与限速约束。

模型每次只看当前页与自己的笔记，拿不到整本书文件、shell 或工具——这一点 README 专门写了，是防注入的设计，不要改掉。

扫描版 PDF 要开 OCR，识别质量决定笔记质量。Kindle 的 mobi、azw 与带 DRM 的书不能直读，得先转 EPUB；去 DRM 涉及授权，自行判断。

作者列了一张实测矩阵：哪些后端在真实页面上跑过，哪些只做了离线测试。八种后端里有五种标注为「对照官方文档检查、尚未实跑」，用之前先小样本验证。

仓库无版本标签，更新以提交为单位。

## 不适用场景

- 只需要某一章的要点，不值得为整本付一遍调用费。
- 手边既没有任何模型订阅，也没有 API Key。
