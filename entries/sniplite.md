## 解决的问题

截屏工具的通病是重。装一个上百 MB 的套件只为按一下 F1，常驻几十 MB 内存，热键按下到出画面之间还有肉眼可辨的停顿。

sniplite 反过来做：抓屏、合成、绘制与选区遮罩这几段热路径用 x86-64 汇编写，其余用 C，不链接 C 运行库，整个程序约 320 KB。它把显卡里的帧直接交给系统在 GPU 上合成，省掉常规抓屏路径的多次拷贝。作者给出的对照中，热键到就绪 12 ms、空闲常驻 11 MB。

功能并不因为小而缺席：贴图置顶（滚轮缩放）、箭头与文字标注、马赛克、聚光灯、取色放大镜、滚动拼接的长截图，另有一个可选本地 OCR 模块——PaddleOCR 的 PP-OCRv6 模型跑在 ONNX Runtime 上，12 MB，全程不出机器。表格识别后按列粘贴，可直接落进表格软件。

八个语言界面跟随系统，便携版免安装；程序不申请管理员权限、不写注册表，设置只生成一个文件，删掉即回到默认。

## 注意事项

仅支持 Windows 10 与 11。OCR 是独立模块，未安装时相关按钮不显示；便携版要选文件名带 with_OCR 的那个。程序常驻托盘，图标可能被系统折叠，需在「其他系统托盘图标」里固定出来。

自动更新每天查一次 GitHub，只比对版本号，可在设置里关闭；便携版不自动更新。全屏程序可让渡热键，避免在游戏里误触。

OCR 模块内含微软 VC++ 运行时的再分发文件，这部分不属于开源，随模块一并分发。

内存占用的大头由显卡驱动持有，想压低可切到低内存模式，代价是抓屏变慢。

## 不适用场景

- macOS 或 Linux 桌面。
- 需要云同步截图库、团队批注与分享链接的场景。
