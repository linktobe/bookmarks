# 开源收藏夹（gh-collection）

**在线浏览：<https://linktobe.github.io/bookmarks/>**

将值得一试的开源项目收录于同一页面：每个条目包含一句话概述、星级评定与标签。

站内另设「个人私藏」一栏，收录不在开源之列、但值得留存的网站与服务，不评星级。右上角有一个不写字、只有日/月图标的开关，点一下即切换；私藏栏整体采用深色配色。

## 星级的评定方式

星级不直接填写，而是逐项勾选满足的标准。五项各计一分，满足几项即为几星，每项评分均可复核。

「解决问题」不作为评分项：收录的项目均需说明其解决的问题，且该条几乎恒为通过，无法区分类别，故改由正文「解决的问题」一节直接陈述。

「有示例」的判定只认仓库内可查看或可运行的示例（示例工程、示例产物、示例素材）；配置模板与测试夹具不计。

| 标准 | 判定条件 |
|---|---|
| 开箱即用 | 下载或克隆后 15 分钟内可观察到效果 |
| 维护活跃 | 近 6 个月内有提交或发布 |
| 文档充分 | 提供可直接照用的最小示例 |
| 版本规范 | 有正式发布，且版本号遵循语义化版本 |
| 有示例 | 仓库内提供可直接查看或运行的示例 |

- **满星（五星）**：五项全部满足
- **四星**：缺一项，多缺于「开箱即用」或「有示例」
- **三星**：缺两项，宜作为参考实现而非直接采用
- **一至二星**：通常不予收录

评分规则实现于 `src/build.py` 的 `CRITERIA`，修改此处即可全站重算。

## 目录

```
gh-collection/
├─ entries/            开源项目，每个项目对应一个 .md
├─ sites/              个人私藏，每个网站对应一个 .md
├─ src/build.py        生成 public/，含评分规则
├─ src/md.py           极简 Markdown 渲染
├─ scripts/            辅助脚本（仓库信息、链接检查）
├─ web/style.css       全站样式
├─ web/favicon.svg     标签页图标
└─ public/             生成结果，Pages 托管此目录
```

## 新增一条

在 `entries/` 下新建 `.md` 文件：

```markdown
---
title: 项目名
repo: owner/repo
license: MIT
language: Python
gh_stars: 12000
pushed: 2026-11-21
added: 2026-11-21
met: 开箱即用, 维护活跃, 文档充分, 版本规范
why_runs: 单文件分发，解压后即可执行
why_alive: 提交频率接近每日
why_docs: 文档为每条命令提供可复制示例
one_liner: 一句话概述该项目的作用。
tags: 工具链, 自动化
---

## 解决的问题
...

## 评分依据
...

## 不适用场景
...
```

`met` 字段填写满足的标准名称，星级由此自动推算。

`why_*` 字段填写**该项目自身**的判定说明，而非通用定义。详情页对应行将直接显示该内容；未填写时则显示标准定义。

「开箱即用」与「版本规范」两项为客观判定，可由脚本核对：前者依据安装步骤，后者依据仓库 release 与标签格式。monorepo 的 `包名@1.2.3` 亦视为语义化版本；仅有提交记录而无 release 者不予计分。

仓库信息（语言、Star 数、最后更新时间）以收录当日为准，可通过辅助脚本获取：

```bash
python scripts/repo_info.py owner/repo
```

## 个人私藏的收录格式

`sites/` 下的条目不做星级评定，也不逐项回答评分问题。它只记三个事实字段加一组标签，正文只回答三个问题。

| 字段 | 内容 |
|---|---|
| `lang` | 网站语言；多语言需逐项写出 |
| `price` | 是否免费：免费 / 部分免费 / 付费 / 未公开 |
| `scope` | 适用范围，一句话 |
| `tags` | 主题标签，用于首页筛选；与开源栏同一套筛选组件 |
| `card` | 可选。卡片右下角那句短述，不填则用「语言 · 费用 · 适用范围」 |

```markdown
---
title: 网站名
url: https://example.com/
lang: 英文（单语种）
price: 未公开
scope: 创意作品集与动效排版
tags: 设计, 动效, 展示
added: 2026-11-22
one_liner: 一句话说明它是什么。
---

## 是什么

## 解决的问题

## 注意事项
```

正文三节固定为「是什么、解决的问题、注意事项」。费用、内测或账号门槛、语言限制与版权条款，均写入「注意事项」；不另设评分表，也不列优缺点清单。

私藏栏整体使用深色配色，与开源栏共用同一套版式、标签筛选与搜索，仅更换色板（`web/style.css` 中的 `body.web`）。

详情页的语言、费用、适用范围改为竖向排列的信息表，字段名在左、取值在右，便于逐项对照。

## 链接状态与元数据刷新

收藏条目最常见的失效原因是仓库变更。为此设有两项自动检查。

第一项看能否打开：

```bash
python scripts/check_links.py
```

该脚本逐一请求 GitHub API，结果分为五类：

| 状态 | 含义 | 页面呈现 |
|---|---|---|
| ok | 正常 | 显示 `GitHub ↗` |
| archived | 已归档：代码可读，作者停止维护 | 显示 `已归档 ↗`，详情页提示最后提交日期 |
| moved | 改名或转移，API 返回新的 full_name | 显示 `已迁移 ↗`，指向新地址 |
| missing | 404 / 410，或仓库被禁用 | 卡片标红「链接失效」，详情页顶部提示 |
| unknown | 网络错误或限流 | 不作判定，照常显示 |

结果写入 `data/link-status.json`（不纳入版本库）。检查本身不超过 24 小时一次：脚本发现有未过期的结果会直接跳过，工作流用 Actions 缓存把上一次的结果取回来，因此连续推送不会反复请求外部站点；需要立刻重查时执行 `python scripts/check_links.py --force`。

定时任务每天在两个时点各触发一次（04:17 与 16:17 UTC）。GitHub 的定时触发并不准时，被推迟数小时是常态，所以设两个时点兜底：哪一次先落地就由它复查，另一次会发现 24 小时窗口未过期而跳过。条目未变更时，这次复查就是当天唯一的一次外部请求。

`sites/` 下的网站同样会逐个访问首页：返回 404 / 410 记为失效，需登录或限流记为不作判定。网站不判断内容变更，只看能否打开。

单个仓库检查失败不会阻断发布：链接失效应被标注，而非导致整站无法发布。

第二项刷新会过期的那两个字段：

```bash
GITHUB_TOKEN=... python scripts/update_meta.py
```

条目里的 `gh_stars` 与 `pushed` 是收录那一刻的快照，仓库一有新提交就会失真，而卡片上的「更新于」与评分依据里的「最近一次提交于」都由它们渲染。这个脚本逐个取回最新的星标数与最近提交日期，写入 `data/repo-meta.json`（同样不纳入版本库），构建时覆盖快照值，并把评分依据里引用的旧日期一并改成新日期，避免卡片与判定表各说各话。

它不回写仓库里的 Markdown：条目是收录时的判定记录，属于历史；线上展示的数据每次构建重新取。超过 180 天没有提交的条目会在脚本输出里单列出来，提醒复核「维护活跃」这一项——日期可以自动刷新，是否仍算活跃仍需人来判断。

这两项都在工作流的每次运行里执行，定时触发与推送触发一视同仁。

## 交互与动效

页面动效仅使用 `transform` 与 `opacity`，不触发重排，并在 `prefers-reduced-motion: reduce` 时全部关闭。

| 动效 | 触发时机 |
|---|---|
| 页头分层入场 | 打开页面 |
| 卡片依次升起 | 打开页面（按序号递增延迟） |
| 卡片悬停上浮 | 指针移入卡片，伴随边框与阴影变化 |
| 星级微放大 | 指针移入卡片 |
| 筛选结果重入 | 切换标签或清空筛选后重新出现的卡片 |
| 顶栏底色加深 | 页面滚动超过 6 像素 |
| 页面转场淡入 | 支持的浏览器中，列表与详情页之间跳转 |

样式表引用带内容哈希（`style.css?v=xxxxxxxx`），修改样式后无需担心浏览器沿用旧文件。


## 部署

推送至 GitHub 后，于 **Settings → Pages → Source** 选择 **GitHub Actions**。此后修改 `entries/` 或 `sites/` 均会触发自动重建与发布。

## 图标来源

标签页图标为 32×32 的 SVG，书签图形取自 [Lucide](https://lucide.dev) 的 `bookmark` 图标（ISC 许可），按本站配色重绘为实心版本。位于 `web/favicon.svg`，构建时复制到 `public/assets/`。
